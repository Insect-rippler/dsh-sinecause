# 变更记录

## 0.1.9 — 2026-10-25

### notify 支持 ntfy

飞书的自定义机器人不是每个租户都有（个人版/某些策略下只显示应用机器人），
所以加了一条不需要任何注册的通道：**ntfy**。

```
{ "webhook": "https://ntfy.sh/你的主题名" }
```

按地址自动判断报文格式：`open.feishu.cn` 走飞书的 JSON，其余按 ntfy 的纯文本 + `Title` 头。

- 设置文件的键统一成 `webhook`（`feishuWebhook` 仍然兼容）；
- 手机上装 ntfy App 订阅同一主题即可收推送，不用注册、不用审核、不用公网地址。
## 0.1.8 — 2026-10-25

### 新增：`notify` 工具（单向下通知）

新入口 `dsh-sinecause/notify`，一个 `notify({ text })` 工具：把值得他知道的一句话推出去。
先用飞书群机器人（自定义机器人 webhook）——建个只有自己的群、加个机器人就能推，
不需要审核、不需要公网地址。

- webhook 地址是凭据：解析顺序 配置 → `state/notify.json` → `SINECAUSE_FEISHU_WEBHOOK`，
  调用时才读，改配置不用重启；
- 只对工作区内的会话可见；
- 飞书 HTTP 200 也可能失败（业务 code≠0），两种都当失败处理。

选它的理由：实测这台机器直连 Telegram / Discord 都不通，飞书和企业微信群机器人可达。
**只做单向**——双向需要能收事件的通道，另议。
## 0.1.7 — 2026-10-25

### 修复：没有门槛时不再写心跳状态文件

时钟每次叫醒都会清一次门槛，而 `clear()` 不管有没有这个会话都写一遍盘——
表现是 `state/heartbeat.json` 每 10 分钟被重写一次，哪怕里面是空的。

现在没有门槛就直接返回，不碰文件。附带好处：这个文件"存在且有内容"重新变得可信。
## 0.1.6 — 2026-10-25

### 新增：尾部立场回声

人格现在出现在两处：系统提示开头（order 1）和上下文尾部（`## 立场`，order 240）。

**这不是重复，是必要的冗余。** 系统提示的注意力会随上下文变长而衰减——
1000 token 在 2000 里占一半，在 80000 里只剩百分之一。开头和结尾是最能牵引注意力的两个位置，
同一件事在两处各说一次，人格才不至于在一小时的长会话里悄悄失效。

- 尾部那份和开头那份**同源**（同一个文件），不会各说各话；
- `echo: false` 可以关掉，但开头那份不受影响；
- 顺序排在记忆（250）与目标（300）之前——先"我是谁"，再"我记得什么"，最后"我此刻做什么"。
## 0.1.5 — 2026-10-25

### 新增：persona —— 人格放进系统提示的开头

新入口 dsh-sinecause/persona。它把 `<workspace>/state/persona.md` 注入到**系统提示**里，
不是上下文末尾——位置由 DSH 自己的顺序表决定：

```
HARNESS_IDENTITY        -1000   宿主说"你是 DSH 上的 agent"
DEPLOYMENT_PERSONA_PREFIX    0   宿主留的人格空槽
  ← 我们在这里（order 1）
PLAN_POLICY              500    策略
TOOL_*                 1000+    工具说明
```

**人格先于目标、先于一切可执行规则**：goal 可以改可以弃，persona 不会因为它们而变。

几条定死的语义：

- 文件不存在或为空 → **什么都不注入**，不拿默认人设填坑；
- 只对工作区内的会话生效，子代理没有；
- 正文按 mtime 缓存，超长截断（人格挤掉工具说明是坏交易）；
- `interpolate: false`——人格正文是用户数据，不能当提示词模板。

包里带 `persona.example.md`：一份只有结构和规则的空白模板。内容由部署者自己写，
我们不该替别人定义他是谁。
## 0.1.4 — 2026-10-25

### 新增：heartbeat 工具（取代早期 wait 的设想）

她知道手上的事当下做不了时，可以让自己安静久一点：

```
heartbeat({ idleMinutes: 120, reason: '在等一个外部回复' })
```

- **按最近一次动静计时**，不是墙上时钟：任何动静都会重新开始计；
- 醒一次自动回到默认节拍（10 分钟），不需要她记得撤销；idleMinutes: 0 立刻恢复；
- 门槛写在 `state/heartbeat.json`，重启后还在；
- 只对工作区内的会话可见。

和 schedule 的区别：schedule 到点就响，heartbeat 只要有人在说话就永远不响——
后者才是"保活"。

早期 wait 设计里那套"强行结束一轮"（借 locked 收轮）**作废**：模型说完话一轮自然就结束。
设计稿 `docs/heartbeat.md`。

## 0.1.2 — 2026-10-25

### 修复

- **零证据的条目也能被召回。** 分数是「2×词法 + 新鲜度 + 重要度」，后两项与提问无关，
  于是与提问毫无关系的记忆靠"比较新、比较重要"就能拿到 1.00 的基础分并越过门槛。
  现在没有任何词法证据的条目直接得 0 分：新鲜度和重要度只用来在**相关条目之间**排序。
- **一个共同虚词被当成证据。** 标题按双字重合给分时，"什么""怎么"这种共同的双字
  会把两条毫不相干的记忆连起来（问"她该叫什么名字"命中"相似阈值为什么是 0.75"）。
  现在重合按**提问覆盖度**计算，且低于 0.25 不算证据。

门槛仍是 2：病根不在门槛高低，在"零证据也能拿分"。再要提高召回只能等向量进入召回，
下调分数线只会把噪声一起放进来。

## 0.1.1 — 2026-10-25

### 修复

- **改正文后摘要不重算。** `update({ content })` 不带 `summary` 时，摘要保留旧值：
  召回块渲染的是 `title：summary`，于是她会读到旧内容；更糟的是 `embeddingHash`
  由 title+summary+keywords 组成，摘要不动它就继续匹配，旧向量永远不会被判过期重算。
  现在正文变而摘要未给时自动重算。
- **召回几乎捞不出东西。** `lexicalScore` 只用关键词/标签/实体做"查询包含关键词"的精确判断，
  **标题完全不参与打分**，中文又没有空格——实测 10 条库、一句正常提问只召回 1 条。
  现在标题与关键词按双字重合给部分分（最多 2 分，半个关键词命中的分量）。
- **低位真匹配被丢弃。** `sameSubjectEntries` 先按分数截断 12 条再过滤，
  库里条目一多，真正的同类条目只要原始分数排在第 12 名之后就会被丢掉。改成全量过滤后截断。

### 打包

- `scripts/` 进入 `files`：从 npm 安装也能拿到 `download-model.ps1`（离线下载向量模型）
  和 `check-embedding.mjs`（池化与相似度验收）。
- **`LICENSE` 进包根。** 之前许可证文件只在仓库根，npm 包里没有，registry 页面上显示"无许可证文件"。
- **忘了配 `workspaceRoot` 的报错改写。** 原文案只说"用 `file:` 装法时"，但从 npm 装的包
  同样在 `node_modules` 里，是同一个坑；现在把两种装法都写清楚，并点名 `link:` 不需要配。

## 0.1.0 — 2026-10-24

首个发布版本。

- **goal**：`plan` 工具（create / list / done / block / add / timer / finish / abandon）；
  目标与计划注入在上下文**末尾**，内容不变不重发，变了替换旧快照。
- **memory**：常驻档案（`anchor` / `self`）每次请求注入，流水（`skill` / `fact` /
  `episode` / `promise`）按分数召回；新旧判断用 bge-base-zh-v1.5（768 维）向量，
  过时有两个去处（`supersede` 让位、`expire` 降权）；整理由计数触发。
- **clock**：空闲时按间隔叫醒，只叫最近活跃的工作区会话，子代理不叫。
- 工作区隔离：三个插件都只对 cwd 落在 `workspaceRoot` 下的会话生效。
- 已知限制见仓库 README 的「限制」一节。
