# heartbeat：保活，不是任务管理

> 状态：已实现（0.1.4）。工具名 `heartbeat`，住在 clock 插件里。

## 它解决什么问题

DSH 自带的任务管理已经能处理"任务受阻"——受阻就停，等下一次输入。所以再做一个
"让 AI 决定什么时候停下"的机制是多余的。

缺的是另一半：**当她知道这事当下做不了、又不愿被每十分钟叫一次时，能说"让我安静两小时"**。

默认节拍是每 10 分钟一跳（快速迭代期）。夜里八小时就是 48 次唤醒——大部分是空转。
`heartbeat` 让她自己把这个门槛调大。

## 语义

```
heartbeat({ idleMinutes: 120, reason: '在等一个外部回复' })
```

意思是：**从最近一次动静算起，安静满 120 分钟再叫我。**

- 任何动静都会重新计时——她说一句话、我回一句话、工具调用，都算；
- 醒一次就**自动回到默认节拍**，不需要她记得撤销；
- `idleMinutes: 0` 立刻恢复默认；
- 门槛落在 `state/heartbeat.json`，重启后还在（关机期间没着的等待不该消失）。

## 与定时任务的区别

| | 触发条件 | 典型用途 |
|---|---|---|
| `schedule` / `plan` 的 `timer` | **墙上时钟**：到点就响 | "明早九点提醒我" |
| `heartbeat` | **安静时长**：多久没动 | "两小时内别烦我" |

两者不能互相替代：定时任务在人还活跃时也会响；heartbeat 只要有人在说话就永远不响，
这正是"保活"该有的行为。

## 实现

- `src/clock/heartbeat-store.js`：按会话 id 存 `{ idleMs, setAt }`；
  文件损坏当作没有门槛（回到默认节拍），写不进去就只在内存里生效。
- `src/clock/decide.js`：`pickTarget` 支持每个会话自带 `minIdleMs`，优先于全局间隔。
- `src/clock/index.js`：tick 时把门槛传给判定；醒过就清掉。工具注册在 `agent.ctx` 上，
  只对工作区内的会话可见。

## 不做的事

- **不强行结束一轮。** 早期设计稿里那套「pre-step reject 借 `blocked` 收轮」是多余的：
  模型说完话，一轮自然就结束了。`wait` 那个名字和那套机制一起作废。
- **不做条件等待**（"等文件出现"）。那需要外部事件源，与心跳是两件事。
- **不与 clock 的默认节拍割裂。** heartbeat 调的就是同一台时钟的门槛，
  不存在"两套唤醒系统"。
